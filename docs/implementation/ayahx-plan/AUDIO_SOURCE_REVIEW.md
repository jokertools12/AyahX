# Quran Foundation and EveryAyah source review (Task 0.1)

Read-only review of official documentation and repository pages checked 2026-10-15. This is source due diligence, not a legal conclusion, identity approval, or source activation. No credentials, API writes, audio downloads, or private media were accessed.

## Quran Foundation / Quran.com Content API v4

Official sources: [Developer Terms](https://api-docs.quran.foundation/legal/developer-terms/), [Content API migration guide](https://api-docs.quran.foundation/docs/quickstart/migration/), [v4 fields](https://api-docs.quran.foundation/docs/api/field-reference/), [verses-by-script endpoint](https://api-docs.quran.foundation/docs/content_apis_versioned/4.0.0/quran-verses-by-script/), [recitation audio files endpoint](https://api-docs.quran.foundation/docs/content_apis_versioned/4.0.0/recitation-audio-files/), and [font rendering guide](https://api-docs.quran.foundation/docs/tutorials/fonts/font-rendering/), and [Connected Apps attribution/requirements](https://api-docs.quran.foundation/docs/connected-apps/).

- Developer Terms updated2026-10-11 cover API text, metadata and audio. They permit in-app display subject to conditions and prohibit modifying Quran text. In-app subscriptions/ads may be permitted; separately selling or redistributing raw content requires a signed commercial license. Backend delivery within the app is not automatically redistribution.
- Ordinary caching/storage is limited to one week. Content Sync is the documented offline path for supported resources, with refresh at least every seven days when connected and changes applied; it does not permit prepackaged content. Documented fonts/Mushaf images have separate integrated-app conditions, including an active Developer Console account and accessible credit.
- Social-video incorporation is described as end-user use when accessible Quran Foundation attribution accompanies the video. Recording-specific ownership or additional conditions still need verification.
- Attribution guidance in the Connected Apps documentation gives “Quran data provided by Quran.Foundation.” It also asks that translations, tafsir editions, and recitations be credited by named source/edition. Use the exact source-specific attribution when surfaced; no per-recording audio credit string was identified in the reviewed endpoint docs.
- Current Content API docs require backend OAuth2 Client Credentials with `content` scope, `x-auth-token`, and `x-client-id`; the migration guide identifies `api.quran.com/api/v4` as the older unauthenticated integration and the Quran Foundation endpoints as the current path. API responses may be rate-limited (`429`); documentation says respect limits, but no numeric quota was found. The reviewed docs do not specify CORS headers. Backend use is the documented Content API model; do not infer browser CORS or permission from an audio URL.
- v4 fields expose `text_uthmani`, `text_qpc_hafs`, `text_indopak_nastaleeq`, `verse_number`, and `verse_key` (`chapter:verse`). Script-specific routes identify supported script names; QCF font rendering docs call for a Mushaf selection and matching fonts. These API fields/keys do not by themselves approve an AyahX riwayah, numbering convention, or text/font fingerprint. No immutable text revision or API response checksum was found in the reviewed reference pages.
- Recitation endpoints document audio file URLs and recitation/verse identifiers, but no audio-byte checksum or immutable recording revision was found in the reviewed API reference. API access rights for in-app display do not establish permission to cache/redistribute underlying third-party recitation recordings beyond the Developer Terms.

### AyahX integration evidence and risk

- `server/routes/quran.ts:153–174` requests `text_uthmani`, `verse_number`, and `verse_key`. `server/services/quranFoundationService.ts:145–205` uses authenticated QF first, then automatically falls back to public `https://api.quran.com/api/v4`; `src/lib/quranFoundationApi.ts:40,159` also targets that legacy base directly. QF says direct Quran.com service use is also subject to Quran.com Terms; those terms and the fallback behavior have not been reviewed here, so this review does not approve that fallback.
- `src/data/reciters.ts:30–33, 61–63, 741–764, 938–972` stores EveryAyah folders and an `isOpenLicense` boolean, then constructs public MP3 URLs. The boolean is a project label, not license evidence. `src/pages/CreatePage.tsx:536–544` creates browser `Audio` with the EveryAyah URL. `src/pages/PreviewPage.tsx:986–987` labels QF audio identity `unverified-qf-source:...`, not a byte hash. No audio download/hash was performed.

## EveryAyah

Official sources: [EveryAyah home](https://everyayah.com/), [recitations page](https://everyayah.com/recitations_ayat.html), [data directory](https://everyayah.com/data/), and [timings disclaimer](https://everyayah.com/data/timings_files/000_disclaimer.txt).

- The official pages list reciter/audio folders, ayah MP3s, ZIP/MD5 links, and timing ZIPs. The recitations listing labels some entries as Warsh and explicitly shows missing files for at least one Warsh recording. Directory timestamps are visible, but no immutable release/version contract or riwayah/numbering specification for the full catalogue was found. The MD5 links are not SHA-256 content identity proofs; no file was fetched or hashed.
- No site-wide license or clear audio recording rights grant was found on the reviewed EveryAyah pages. The listed recordings include multiple reciters and source labels; public availability, direct MP3 URL, ZIP, or MD5 does not prove rights to stream through AyahX, cache on the server, redistribute, or incorporate into exported video. Obtain recording-specific permission/terms and attribution before activation. No numeric rate limits or CORS policy were documented; browser playback behavior must not be treated as a rights grant.
- The timing directory's official disclaimer says `© VerseByVerseQuran.com`, requires a link to that site from the product and website when using those timings, calls the files “as-is,” and warns they may not be 100% accurate. It links to `http://versebyversequran.com/site/license`, which was inaccessible during this review. Thus exact timing license terms and redistribution rights remain unverified. This disclaimer covers timing files, not the separate recitation recordings.

## Gate / next action

QF Content can be displayed within the documented application conditions, with the stated cache, sync, attribution, and redistribution limits; verify AyahX's active account/rights declarations and each selected audio's source terms before implementation. Review and resolve the legacy automatic QF-to-Quran.com fallback separately. For EveryAyah, acquire the referenced timing license and recording-specific rights/attribution, then verify the exact recitation, riwayah, coverage, revision, and SHA-256 against the selected audio before any timing or rendering use. Nothing in this document activates a source or approves content.
