# K3: بيانات YouTube الوصفية فقط

`scripts/prepare-d4-youtube-metadata.ts` يقرأ `recitations.channel` و`recitation_chapters.audio_url` من القاعدة الفعلية، ويحسب التلاوات والروابط والفيديوهات المميزة. لا يثبت العدد المذكور في الطلب كثابت. اختلاف العدد الفعلي عن النص يُعرض في تقرير الدفعة.

المشغّل الرئيسي وحده ينفذ أوامر القاعدة والفحص الخارجي. هذا السكربت لا يقبل `--apply` مع `--target production`. التطبيق على الإنتاج يمر بخطة SQL مستقلة وحارس القبول والنسخة الاحتياطية المعتمدين.

مثال تحضير محلي، مع استبدال مسارات الأدلة الخاصة خارج المستودع:

```powershell
npx tsx scripts/prepare-d4-youtube-metadata.ts --target local --local-db ayahx_d4_clone --checkpoint C:\private\youtube-metadata.jsonl --sql-output C:\private\youtube-metadata.sql --report docs/data/youtube-metadata-local.json --check-network --apply
```

الإنتاج: نفس الخيارات مع `--target production`، ودون `--local-db` أو `--apply`. اختبار صغير اختياري بـ `--limit 1`: يخرج تقريرًا `complete=false` ولا يُنتج خطة تطبيق حتى تغطية جميع الفيديوهات. استكمال التشغيل يستخدم ملف checkpoint نفسه.

الفحص يستخدم oEmbed الرسمي `https://www.youtube.com/oembed`، طلبًا واحدًا لكل فيديو، بفاصل بدء لا يقل عن ثانية، ومن دون retries. `Retry-After` في HTTP 429 يحجب الطلبات التالية عالميًا حتى انقضاء الفترة؛ الغياب أو القيمة غير الصالحة ينتج انتظارًا 60 ثانية. مهلة 25 ثانية تغطي الاستجابة والجسم. تُغلق وصلة القاعدة قبل الطلبات الخارجية، وتُفتح للقراءة والتحضير بعد انتهائها مع مقارنة بصمة أهداف الكتالوج.

ملف checkpoint خارج Git، append-only مع سلسلة SHA-256 و`fsync`. يسجل نية الطلب قبل تنفيذه ثم النتيجة. إذا قُطعت العملية أثناء الطلب يبقى الفيديو `YOUTUBE_OEMBED_INTERRUPTED` عند الاستئناف، دون إعادة الطلب أو اختلاق نجاح. نهاية ملف مقطوعة أو بصمة متغيرة توقف التشغيل وتحفظ الأدلة؛ لا تُصلح أو تُحذف صامتًا. التقرير يتضمن بصمة الملف.

المحفوظ من oEmbed: الحالة والتاريخ وHTTP status وعنوان الفيديو والقناة ورابط القناة الرسمي؛ لا HTML ولا صور مصغرة ولا بايتات صوت/فيديو. يُكتب صف مستقل لكل تلاوة وسورة في `recitation_youtube_sources`، ومرجع `provider_original` غير نشط في `recitation_source_urls` لتسجيل حالة metadata فقط. لا يتغير `recitation_chapters` ولا صحة الصوت ولا التوقيت ولا النشر. `available` هنا تعني توفر metadata ولا تثبت وجود صوت قابل للريندر أو حقوق استعماله.

حقوق الصف الجديد `unknown`؛ حقوق وإثباتات بشرية موجودة تُحفظ عند تحديث metadata. Replay يتجاهل ضجيج `last_checked_at` إذا لم تتغير metadata ويخرج صفر تغييرات. خطة التغيير تسجل audit بنفس السلسلة وحارس المعاملة المعتمد، ولا تحتوي روابط موقعة. إصدار SQL لا يعتمد على ترتيب وصول الشبكة.

التحقق المحلي البرمجي: سبعة اختبارات وحدات للتحقق من المصادر الرسمية، حذف HTML، الانتظار، سلامة/استئناف checkpoint، المراجع غير النشطة، حفظ الحقوق وidempotency، ورفض التغطية الناقصة. فحص الشبكة الحقيقي وتطبيق MySQL وإثباتات الإنتاج ينفذها المشغّل الرئيسي وتُسجل منفصلة؛ نجاح الوحدات لا يقوم مقامها.
