# 02 — خطة لوحة الأدمن الكاملة لـ AyahX

> الهدف: لوحة تحكم احترافية تدير **كل شيء** في الموقع (القرآن والقراء والتوقيتات والصوت، الخلفيات والأنماط، الفيديوهات والريندر، المستخدمين والاشتراكات والدفع، الذكاء الاصطناعي، المحتوى والإعدادات والأمان)، بنفس هوية الموقع، وكل خاصية فيها **مرتبطة فعلياً** بالواجهة العامة ومُختبَرة.
> تعتمد على `01_DATA_PLAN.md` في أقسام القرآن/القراء/التوقيت. اقرأ `00_MASTER_PROMPT.md` أولاً.

---

## 1. مبادئ التصميم والتنفيذ

### 1.1 تطابق التصميم مع الموقع (إلزامي)
1. **استخرج** نظام التصميم الفعلي قبل أي شاشة: `tailwind.config.ts`، ملف CSS الرئيسي (متغيرات `--primary` إلخ)، `components.json` (shadcn)، الخطوط المستخدمة، الألوان الذهبية/الزمردية، أنصاف الأقطار، الظلال، حركات Framer Motion. وثّقها في `docs/design-tokens.md` وأعد استخدام نفس المتغيرات (لا ألوان جديدة).
2. استخدم مكوّنات `src/components/ui/*` (Radix/shadcn) نفسها؛ أي مكوّن إداري جديد (DataTable, FilterBar, StatCard…) يُبنى فوقها في `src/components/admin/`.
3. RTL كامل، الأرقام والتواريخ بصيغة موحّدة، دعم العربية/الإنجليزية، وضع داكن/فاتح كما في الموقع.
4. إمكانية الوصول: تنقّل بلوحة المفاتيح، `aria-*`، تباين، `prefers-reduced-motion`.
5. **استجابة:** تعمل على الجوال (جداول قابلة للتمرير أو تتحول لبطاقات).
6. لا تغيّر التصميم العام للموقع. التحقق: لقطات مقارنة (الموقع ↔ الأدمن) لنفس المكوّنات (زر، بطاقة، نموذج، جدول، شارة).

### 1.2 المعمارية
- **المسارات:** `/admin/*` في الواجهة (lazy-loaded، حارس صلاحيات)؛ `server/routes/admin/*` في السيرفر، مسبوقة بـ `/api/admin`.
- **كل endpoint إداري:** تحقق JWT ← فحص الدور/الصلاحية ← Zod validation ← تنفيذ ← تسجيل في `audit_logs`.
- **اتفاقيات API موحّدة:** ترقيم (`page`,`limit` ≤ 100)، ترتيب (`sort`), فلاتر، بحث، استجابة `{data, meta}`، أخطاء `{code, message, detail}`، ترويسة `X-Request-Id`.
- **حالة الواجهة:** TanStack Query (مفاتيح موحّدة + إبطال بعد التعديل)، نماذج بـ react-hook-form + Zod مشتركة من `shared/`.
- **الحذف:** soft delete حيث يلزم (users, saved_videos, recitations)، تأكيد مزدوج للحذف الدائم، سلة قابلة للاستعادة 30 يوماً.
- **العمليات الثقيلة** (استيراد، محاذاة، ريندر، تنظيف): عبر BullMQ ولها شاشة تقدّم، لا تعمل داخل طلب HTTP.
- **كل إعداد قابل للتعديل** يخزَّن في `app_settings` (مفتاح/قيمة/نوع/مجموعة/عام أم سري) ويُقرأ عبر طبقة كاش مع إبطال فوري.

### 1.3 الأمان
- أدوار وصلاحيات دقيقة (قسم 2)، 2FA (TOTP) إلزامي للأدوار العليا، انتهاء جلسة، قفل بعد محاولات فاشلة، سجل جلسات قابل للإنهاء.
- حماية CSRF/Origin على مسارات الأدمن، CORS مقيّد، Rate limit أشد على `/api/admin`.
- لا تُرجِع الأسرار أبداً (مفاتيح API تظهر مقنّعة `••••1234`)؛ التعديل بإدخال قيمة جديدة فقط. تخزين الأسرار مشفّرة أو في البيئة، لا في الكود.
- كل إجراء حساس (حذف، تغيير دور، اعتماد دفع، انتحال مستخدم) يتطلب تأكيداً ويُسجَّل (من/ماذا/متى/IP/قبل/بعد).
- اختبارات IDOR/RBAC لكل مورد (قسم 7).

## 2. الأدوار والصلاحيات

| الدور | الصلاحيات |
|---|---|
| `super_admin` | كل شيء بما فيها الأدوار، الإعدادات السرية، الحذف الدائم، الأمان |
| `admin` | كل شيء عدا إدارة super_admin والإعدادات السرية |
| `content_manager` | مكتبة القرآن والقراء والتوقيت واعتماده، الخلفيات والأنماط والقوالب، المحتوى |
| `finance` | الاشتراكات والدفع والكوبونات والتقارير المالية |
| `support` | المستخدمون (قراءة/تعديل محدود)، التعليقات والبلاغات، رسائل الدعم |
| `moderator` | الفيديوهات والتعليقات والبلاغات |
| `analyst` | تقارير وتحليلات (قراءة فقط) |

- الصلاحيات تُعرَّف كمفاتيح (`recitations.write`, `timings.approve`, `payments.review`, `users.impersonate`, …) في جدول `permissions` و`role_permissions`، ويمكن للـ super_admin تعديلها من الواجهة.
- مصفوفة صلاحيات كاملة تُولَّد تلقائياً في `docs/admin-permissions.md` وتُختبَر (قسم 7).

## 3. أقسام اللوحة (ما يجب بناؤه بالتفصيل)

> لكل قسم: **الشاشات** · **الحقول/الإجراءات** · **API** · **الربط بالواجهة العامة** · **القبول**.

### 3.1 لوحة المؤشرات (Dashboard)
- **بطاقات:** مستخدمون جدد/نشطون، فيديوهات اليوم/الأسبوع، ريندرات (نجاح/فشل/قيد التنفيذ)، طابور الريندر، الإيراد، طلبات دفع معلّقة، بلاغات مفتوحة.
- **رسوم:** نمو المستخدمين، الفيديوهات يومياً، نسبة نجاح الريندر، أكثر السور/القراء استخداماً.
- **صحة النظام (مباشر):** MySQL (زمن الاستجابة)، Redis، عامل الريندر (Chromium+FFmpeg)، عامل المحاذاة، الـ Aligner Space (`/health` + الحصة)، مساحة التخزين، مزوّدو الصوت (حالة آخر فحص).
- **تنبيهات:** فشل ريندرات متتالية، تعطّل مزوّد صوت، امتلاء التخزين، حصة الـ Aligner، طلبات دفع متأخرة.
- **API:** `GET /api/admin/dashboard/summary|charts|health`. **قبول:** الأرقام تطابق استعلامات DB مباشرة (اختبار)، والتحديث دون إعادة تحميل.

### 3.2 مكتبة القرآن (القسم الجوهري)

#### 3.2.1 السور والآيات والنص
- جدول 114 سورة: الاسم (ع/إنجليزي/لاتيني)، مكية/مدنية، عدد الآيات، الجزء/الصفحة، `has_basmala`، حالة اكتمال النص.
- تفاصيل السورة: قائمة الآيات والكلمات، **عارض نص** بالخط المعتمد، مقارنة النص بين إصدارين (diff)، فحص التكامل (checksum، عدد الكلمات).
- **النص القرآني للقراءة فقط:** لا حقل تحرير. التحديث الوحيد = «استيراد إصدار نص جديد» (مصدر محدد + dry-run + diff + موافقة super_admin + تفعيل). أي تعديل يدوي ممنوع ويُرفض في السيرفر.
- الترجمات والتفاسير: إضافة ترجمة (لغة/مترجم/رخصة)، استيراد ملف، تفعيل/تعطيل، ترتيب.
- الآيات المميزة/القوالب الجاهزة (آية الكرسي، خواتيم البقرة، …): مجموعات قابلة للإدارة (اسم، سورة، من–إلى، صورة، ترتيب، ظهور).
- **ربط الواجهة:** صفحة اختيار السورة/الآيات تقرأ من `/api/catalog/surahs` و`/api/quran/ayahs`؛ مجموعات الآيات المميزة تظهر في شاشة "آيات شهيرة".

#### 3.2.2 الروايات والمصاحف
- قائمة الروايات (حفص، ورش، قالون، شعبة…) مع `aligner_code`، تفعيل/تعطيل، ترقيم الآيات الخاص بكل رواية.
- ربط الرواية بإصدار النص. **قبول:** تعطيل رواية يخفيها من الواجهة فوراً.

#### 3.2.3 القراء
- **جدول:** صورة، الاسم، الدولة، عدد التلاوات، التغطية، الحالة، مميّز؟، الترتيب. بحث/فلترة (رواية، أسلوب، مستوى توقيت، حالة).
- **نموذج القارئ:** الاسم ع/إنجليزي، slug، نبذة، دولة، صورة (رفع مع قص/ضغط)، روابط، وسوم، مميّز، ترتيب، حالة.
- **إجراءات:** دمج قارئين مكررين (يُنقل كل التلاوات)، تفعيل/إخفاء، ترتيب بالسحب، حذف ناعم.
- **ربط الواجهة:** قائمة القراء في اختيار القارئ تُجلب من `/api/catalog/reciters`؛ المميّزون أولاً؛ الإخفاء/الترتيب ينعكس فوراً (إبطال الكاش).

#### 3.2.4 التلاوات (Recitations)
- **جدول:** القارئ، الرواية، الأسلوب، المزوّد، التغطية (آيات/سور)، مستوى التوقيت وجودته، الحالة، آخر فحص صوت.
- **صفحة التلاوة:** البيانات الأساسية؛ **سور متاحة** (مصفوفة 114 خلية بألوان: صوت+توقيت معتمد / صوت فقط / ناقص)؛ وضع الصوت (`surah_slice/ayah_clips`)؛ سلسلة المصادر والـ fallback المسموح؛ الرخصة والإسناد؛ إصدار QUD.
- **إجراءات:** نشر/إخفاء/إيقاف، إعادة فحص الروابط، إعادة استيراد التوقيتات، تشغيل محاذاة للسور الناقصة، تحميل تقرير التغطية، تصدير JSON.
- **قبول:** لا يمكن نشر تلاوة تغطيتها تحت العتبة المضبوطة (إعداد) إلا بتأكيد صريح.
- **ربط الواجهة:** الواجهة تُظهر فقط `published`، وتحدد بها شارة التوقيت.

#### 3.2.5 المزوّدون ومصادر الصوت
- جدول المزوّدين (QUD, EveryAyah, MP3Quran, QDC/Quran Foundation, Way2Quran, TVQuran, Tarteel, Upload…): الاسم، الرابط الأساسي، **قائمة المضيفين المسموحة (SSRF allowlist)**، الأولوية، مفعّل؟، حالة الصحة، آخر فحص، ملاحظات الرخصة.
- زر **اختبار الاتصال** (HEAD/Range على رابط عيّنة) ونتيجته مسجّلة.
- **إضافة مصدر جديد:** معالج (Wizard) يختار نوع المحوّل (`CatalogAdapter`)، يدخل الإعدادات، يشغّل اختباراً، ثم يستورد.
- **قبول:** تعطيل مزوّد يوقف استخدامه في `AudioResolver` ويُسجَّل أثره (كم تلاوة تتأثر) قبل التأكيد.

#### 3.2.6 مركز الاستيراد والمزامنة
- **مهام الاستيراد** (من Releases/HF/Aligner/ملف): بدء، **dry-run**، تقدّم حي، سجل أخطاء، إيقاف/استئناف/إعادة، جدولة (يومي/أسبوعي) للتحقق من إصدار جديد من QUD.
- شاشة **الفروق:** ما الذي سيُضاف/يتغيّر/يُحذف قبل التطبيق.
- حماية: لا استيراد يستبدل توقيتاً `approved` بدون إذن صريح (خيار "احتفظ بالمعتمد").
- **قبول:** مهمة مقطوعة تُستأنف دون تكرار؛ سجل كامل لكل مهمة.

#### 3.2.7 مدير التوقيتات والمحاذاة
- **قائمة الجودة:** كل (تلاوة × سورة) مع حالة (`none/estimated/aligned/needs_review/approved`)، نسبة التغطية، عدد التحذيرات.
- **محرر التوقيت:** موجة صوتية (WaveSurfer أو مكافئ)، حدود الكلمات قابلة للسحب، تشغيل مقطع/كلمة، تكبير، اختصارات، تراجع/إعادة، مقارنة بالنسخة المصدرية، حفظ كإصدار جديد.
- **المدققات الآلية** (D6) وعرض نتائجها بجانب الآية.
- **اعتماد:** فردي أو جماعي بشروط؛ رفض بسبب؛ سجل إصدارات مع الرجوع.
- **المحاذاة:** إعداد الـ Aligner (Base/Large، GPU/CPU، الرواية، padding)، إنشاء مهام لمدى آيات أو سور، **مراقب الحصة** (آخر 402/429، موعد إعادة المحاولة)، زر إيقاف مؤقت للطابور، نتائج `needs_review`.
- **ربط الواجهة/الريندر:** الريندر يقرأ `approved` فقط (للـ Aligner) أو `aligned+` (لـ QUD)؛ تغيير الاعتماد ينعكس في الريندر التالي (اختبار).

#### 3.2.8 الابتهالات والأناشيد
- المنشدون (مثل نصر الدين طوبار، سيد النقشبندي…): ملف شخصي، مقاطع (ملف صوت/رابط، مدة، `surah:0`)، قص زمني، **نص مفرّغ + توقيت** (تفريغ Gemini كمسودة `unverified` ثم مراجعة بشرية)، الرخصة، حالة النشر.
- **ربط الواجهة:** استوديو الابتهالات يعرض المنشورة فقط.

### 3.3 الأصول الإبداعية

#### 3.3.1 الخلفيات
- مكتبة صور/فيديو: رفع (حجم/نوع/أبعاد مقيّدة)، توليد صورة مصغّرة، تصنيفات ووسوم، أبعاد (9:16/16:9)، مدة الفيديو، الرخصة والمصدر، ترتيب، مميّز، حالة (نشط/مخفي).
- **استيراد Pexels** من الأدمن: بحث (عبر بروكسي السيرفر)، معاينة، استيراد مع الإسناد، منع التكرار.
- **فحص ملاءمة** يدوي (قائمة مراجعة) قبل النشر: خلو من أشخاص/رموز غير مناسبة.
- تجهيز الفيديو للريندر: الاستخراج المسبق للإطارات مرتبط بالمنطق الحالي (`bg_frames`) — اختبار أن كل خلفية منشورة تُنتج إطارات متحركة فعلاً.
- **ربط:** معرض الخلفيات في الواجهة؛ التصنيفات تُحمَّل من الأدمن.

#### 3.3.2 الأنماط والقوالب والمؤثرات
- **محرّرات قوائم** لكل مجموعة خيارات موجودة في الريندر: أنماط التوهج (golden/soft/neon/pulse/solid/underline)، ظلال النص، أنماط ترويسة السورة، أنماط شارة القارئ، أشكال/ألوان رقم الآية، مواضع العلامة المائية، الإطارات، انتقالات الآيات والشرائح، سرعة الحركة.
- لكل عنصر: الاسم، مفتاح تقني (**يجب أن يطابق ما يفهمه `render-harness.html`**)، معاينة حية، مفعّل؟، ترتيب، متاح لأي خطة (مجاني/مميز).
- **قوالب جاهزة (Presets):** حفظ تركيبة كاملة (خلفية+نمط+خط+مؤثرات) كقالب عام، مع صورة معاينة.
- **مؤثرات الصوت (FX):** إعدادات مسبقة (صدى مسجد، باص، pitch…) وحدودها الآمنة (سقف الصدى).
- **ملفات الخطوط:** رفع/تفعيل خطوط (مع اختبار تغطية الجليفات القرآنية) واختيار الخط الافتراضي.
- **قبول:** لا يمكن حفظ مفتاح نمط لا يعرفه الريندر (قائمة مفاتيح معتمدة مشتركة بين الأدمن والـ harness واختبار يطابقهما).

### 3.4 الفيديوهات والريندر

#### 3.4.1 الفيديوهات
- جدول: صاحب، عنوان، سورة/قارئ، حالة (عام/خاص/محجوب)، مشاهدات/إعجابات/تعليقات، تاريخ، حجم.
- إجراءات: مشاهدة، إخفاء/حجب بسبب، حذف، تمييز (Featured)، نقل ملكية (super_admin)، تنزيل.
- فلاتر متقدمة، تصدير CSV.

#### 3.4.2 مراقب الريندر
- **قائمة المهام** (`render_jobs`): الحالة (queued/running/succeeded/failed/cancelled)، المرحلة، التقدم، المستخدم، الأبعاد/الجودة، المدة، العامل، **ما استُخدم فعلاً** (تلاوة، مزوّد، وضع الصوت، fallback، hash التوقيت).
- **تفاصيل مهمة:** الـ manifest (للقراءة)، لوج المراحل، نتيجة `ffprobe`، رابط الناتج، إطارات عيّنة.
- **إجراءات:** إلغاء (يقتل Chromium وFFmpeg بلا تسريب)، إعادة محاولة، رفع أولوية، إعادة ضبط مهمة عالقة.
- **عمّال وسعة:** `MAX_CONCURRENT_RENDERS`، استهلاك CPU/RAM، طول الطابور، تنبيه عند التراكم.
- **ملفات الجودة (Low/Medium/High/Ultra):** محرر لمعاملات الترميز (CRF، preset، maxrate، bufsize، صوت، Profile) بحدود آمنة وقيم افتراضية قابلة للاستعادة؛ التغيير يؤثر على الريندر الجديد فقط. (القيم الحالية مسجّلة في `VIDEO_PIPELINE_BUGFIX_LOG.md` §7.14.)
- **حدود الريندر:** أقصى مدة (الحالي 600s)، الأبعاد 360–3840، حجم الرفع، التزامن — إعدادات تُقرأ في السيرفر والواجهة معاً.
- **ربط:** صفحة "فيديوهاتي/التصدير" تعكس حالة الأدمن (إلغاء من الأدمن يظهر للمستخدم).

#### 3.4.3 التخزين والتنظيف
- استهلاك `uploads/renders/{userId}` و`bg_*`، أكبر المستخدمين، سياسة الاحتفاظ (حذف الريندرات بعد N يوم)، مهمة تنظيف مجدولة بتقرير، **dry-run** قبل الحذف.
- مهيّأ للانتقال إلى S3/R2 (واجهة تخزين مجردة + روابط موقّعة) — قسم إعدادات التخزين.

### 3.5 المستخدمون والمجتمع
- **المستخدمون:** بحث/فلاتر (خطة، حالة، تاريخ)، ملف المستخدم (بيانات، اشتراك، استخدام اليوم، فيديوهات، نشاط، جلسات)، **تعديل** (اسم، دور، حالة)، **حظر/رفع حظر** بسبب ومدة، إعادة تعيين كلمة المرور (رابط)، **انتحال** (للأدمن فقط، مسجّل، بشريط تحذير)، دمج/حذف حسب سياسة الخصوصية، تصدير بيانات مستخدم.
- **التعليقات والبلاغات:** طابور مراجعة، حذف/إخفاء، حظر المتكرر، كلمات محظورة قابلة للإدارة.
- **المتابعات والمفضلات:** عرض/إحصاء.
- **الإنجازات والأوسمة:** إدارة الـ 10 إنجازات (الاسم، الوصف، الشرط، النقاط، الصورة، مفعّل)، منح/سحب يدوي (مسجّل)، **لوحة المتصدرين**: عرض/تصفير/استبعاد مستخدم، ومسح الكاش.
- **قبول:** حظر مستخدم يمنع الدخول والـ API فوراً (اختبار)، وتعديل شروط إنجاز يغيّر المنح لاحقاً.

### 3.6 الاشتراكات والدفع
- **الخطط:** اسم، سعر، مدة، **الحصص** (محرك المتصفح/الريندر السحابي لكل يوم)، ميزات (جودة قصوى، تصدير 4K، إزالة العلامة، أولوية الطابور…)، ترتيب، مفعّلة. تغييرها يؤثر على `/api/subscriptions/plans` وعلى فحص الحصص الفعلي.
- **عدّادات الاستخدام:** عرض/تعديل يدوي مسجّل، إعادة ضبط يوم، سجل لكل مستخدم. الحجز الذري (لا ازدواج) كما في API الحالي.
- **طلبات الدفع بالمحافظ** (فودافون كاش، اتصالات، أورانج، وي باي، إنستاباي): طابور (معلّق/مقبول/مرفوض)، صورة الإثبات إن وُجدت، المبلغ والرقم، **كشف التكرار** (نفس الرقم/المبلغ/المرجع)، قبول يمدّ الاشتراك **تراكمياً** (لا يلغي المتبقي)، رفض بسبب + إشعار للمستخدم، سجل كامل.
- **كوبونات وعروض:** كود، نوع (نسبة/مبلغ/أيام مجانية)، حدود استخدام وتواريخ، تطبيق على خطة.
- **اشتراكات يدوية:** منح/إلغاء/تمديد مع سبب.
- **تقارير مالية:** إيراد يومي/شهري، حسب الوسيلة، معدل التحويل، المنتهية قريباً (للتذكير)، تصدير CSV/Excel.
- **إعدادات وسائل الدفع:** الأرقام/الحسابات المعروضة للمستخدم، تعليمات، تفعيل/تعطيل كل وسيلة — تظهر في صفحة الترقية فوراً.
- **قبول:** قبول طلب يغيّر صلاحيات المستخدم في الواجهة دون خروج/دخول (اختبار E2E)، وكل قرار مالي له سجل تدقيق.

### 3.7 الذكاء الاصطناعي والتكاملات
- **المزوّدون:** Gemini (تفريغ/ضبط)، بوابة Lovable، Pexels، الـ Aligner، (أي مزوّد مستقبلي): حالة المفتاح (موجود/ناقص، مقنّع)، اختبار اتصال، الحد اليومي، الاستهلاك والتكلفة التقديرية، **اختيار المزوّد صريح لكل وظيفة** (لا fallback صامت).
- **القوالب (Prompts):** إدارة تعليمات الضبط/التفريغ مع إصدارات، وعلامة "مخرجات غير موثّقة".
- **سجل الاستدعاءات:** الوقت، المستخدم، الوظيفة، المزوّد، الحالة، الزمن (بلا محتوى خاص).
- **قيود:** لا مسار يسمح بتعديل نص قرآني بالـ AI (اختبار).
- **قبول:** تعطيل مزوّد يُظهر للمستخدم رسالة واضحة بدل الفشل الصامت.

### 3.8 المحتوى والإشعارات والتواصل
- **الإعلانات والبانرات** (مكان العرض، النص، الجمهور، الجدولة، قابلية الإغلاق).
- **الإشعارات:** إرسال جماعي/مستهدف داخل التطبيق، قوالب، سجل.
- **البريد:** قوالب (ترحيب، استعادة كلمة المرور، قبول/رفض دفع، قرب انتهاء الاشتراك)، اختبار إرسال، إعدادات SMTP (سرية).
- **الصفحات القانونية والثابتة:** الشروط، الخصوصية، **صفحة المصادر والحقوق** (إسناد QUD وCC BY 4.0 وبقية المصادر)، من نحن، تواصل — محرر نص غني آمن (تعقيم HTML).
- **قبول:** تعديل صفحة قانونية يظهر في الموقع فوراً.

### 3.9 الإعدادات العامة
- **عام:** اسم الموقع، الشعار/الأيقونة، وصف، روابط التواصل، لغات متاحة، المنطقة الزمنية.
- **SEO:** عناوين/أوصاف افتراضية، OG، sitemap/robots، Analytics.
- **Feature flags:** تشغيل/إيقاف: الريندر السحابي، المسجّل المحلي القديم، التفريغ بالـ AI، التسجيل، التعليقات، التظليل التقريبي، إلخ — مع نسبة طرح (rollout %) واستهداف.
- **وضع الصيانة:** رسالة ومدة واستثناء الأدمن.
- **الحدود:** حدود الرفع والتحميل، معدّل الطلبات، مدة الريندر، حجم الدفعات.
- **التخزين:** المحلي/السحابي، الاحتفاظ، روابط التوقيع.
- **النسخ الاحتياطي:** جدولة وتشغيل يدوي وسجل واستعادة (مع تأكيد).
- **قبول:** كل إعداد له مستهلك مسجّل في مصفوفة الربط (قسم 4)، وإعداد بلا مستهلك يُرفض في المراجعة.

### 3.10 المراقبة والأمان
- **سجل التدقيق:** من/ماذا/المورد/قبل/بعد/IP/الوقت، فلاتر، تصدير، غير قابل للتعديل.
- **سجلات الطلبات والأخطاء:** بحث بـ `X-Request-Id`، ربط مع Sentry/Datadog عبر `registerErrorHook` الموجود.
- **مركز الأمان:** محاولات الدخول الفاشلة، حظر IP، الجلسات النشطة وإنهاؤها، تنبيهات الأسرار الافتراضية (فحص `JWT_SECRET`)، مراجعة الصلاحيات.
- **الصحة:** `/api/health`, `live`, `ready` معروضة، حالة migrations (المطبّق/المعلّق).
- **أدوات المطوّر:** تصدير/استيراد بيانات الكتالوج، توثيق API، فحص الإعدادات (`doctor`).

### 3.11 التحليلات والتقارير
- الأكثر استخداماً: سور، قراء، أنماط، خلفيات، جودة التصدير، منصات المشاركة.
- القمع: تسجيل ← أول فيديو ← ترقية. معدلات نجاح الريندر ومتوسط زمنه، الأخطاء الأعلى.
- تقارير مجدولة بالبريد + تصدير CSV/Excel. لا بيانات شخصية في التقارير العامة.

## 7. استراتيجية الاختبار

### 7.1 مستويات
- **Unit (Vitest):** المدققات، المحوّلات، `toRenderTimeline`، مُطبِّع التوقيت، حسابات الحصص، منطق الصلاحيات.
- **API/Integration:** كل endpoint إداري: نجاح، تحقق الإدخال، 401/403، **IDOR** (مستخدم يحاول مورد غيره)، ترقيم/فلترة، idempotency، سباقات (حجز الحصة، اعتماد الدفع مرتين).
- **Contract:** مفاتيح الأنماط بين الأدمن والـ harness؛ شكل الـ API العام؛ شكل الـ manifest.
- **E2E (tooling/e2e، Playwright):** مسارات حرجة: دخول أدمن ← إضافة قارئ ← نشر تلاوة ← يظهر في الموقع؛ اعتماد توقيت ← ريندر ← تظليل صحيح؛ قبول دفع ← تفتح ميزة؛ حظر مستخدم؛ تغيير حصة؛ تعديل صفحة قانونية. اختبارات الوكيل (AI) في `tests/agent/` فقط ولا تعمل افتراضياً.
- **ريندر فعلي:** ffprobe + استخراج إطارات (راجع D7).
- **أمان:** RBAC لكل دور × كل مورد (مصفوفة مولّدة)، SSRF، رفع ملفات (نوع/حجم/امتداد مزيف)، XSS في المحرر الغني، CSRF/Origin، rate-limit، عدم تسرّب الأسرار في الردود/اللوج.
- **إمكانية الوصول:** فحص axe على الشاشات الرئيسية + تنقّل بالكيبورد.
- **أداء:** زمن الجداول الكبيرة (آلاف الصفوف)، فهارس، Web Vitals للوحة.

### 7.2 قائمة فحص لكل ميزة (انسخها في التقرير)
```
[ ] الواجهة تعمل (حالة تحميل/فارغ/خطأ/نجاح)
[ ] التحقق من الإدخال في الواجهة والسيرفر
[ ] الصلاحيات (مسموح/ممنوع) + IDOR
[ ] سجل التدقيق يسجّل الإجراء
[ ] الأثر ظاهر في الموقع العام (صف في مصفوفة الربط)
[ ] اختبار آلي يغطيها
[ ] تصميم مطابق (لقطة)
[ ] RTL + جوال + كيبورد
[ ] لا أسرار/بيانات شخصية في الاستجابة أو اللوج
```

## 8. معايير القبول النهائي للمشروع

1. إضافة قارئ + تلاوة + مزوّد + خلفية + نمط + خطة من الأدمن **دون تعديل كود** وظهورها في الموقع.
2. اعتماد توقيت من الأدمن يغيّر تظليل الكلمات في فيديو ناتج فعلاً (يثبت بإطارات).
3. كل صفوف مصفوفة الربط لها اختبار ناجح.
4. لا بيانات/أزرار وهمية؛ ما هو معطّل يظهر معطّلاً بوضوح مع سبب.
5. اختبارات الأمان والصلاحيات تمر لكل الأدوار.
6. `tsc`, `lint`, `test`, `build` نظيفة؛ E2E الأساسي ناجح؛ الريندر الحقيقي مفحوص.
7. التوثيق: `docs/admin-guide.ar.md` (دليل المشغّل)، `docs/admin-permissions.md`، `docs/admin-wiring-matrix.md`، `docs/adding-a-reciter.ar.md`.
8. تقرير أخير بما لم يكتمل ولماذا وما يحتاج قراراً (مثل التخزين السحابي، تكلفة الريندر، رخص الصوت).

## 9. قرارات مفتوحة تحتاج رأي صاحب المشروع (لا تفترضها)

1. **رخص الصوت:** هل يُسمح بإعادة استضافة الصوت أم الاكتفاء بروابط المزوّدين الأصلية؟ يُسمح
2. **تظليل تقريبي (`estimated`):** يبقى متاحاً بتفعيل صريح أم يُلغى تماماً؟ يُسمح
3. **عرض التكرار:** `canonical` أم `recited` كافتراضي؟ recited
4. **الـ Aligner:** الاكتفاء بالـ Space العام أم تجهيز استضافة ذاتية لاحقاً؟ نعم
5. **تخزين الريندرات:** متى الانتقال من القرص المحلي إلى S3/R2؟ في الحال
6. **2FA:** إلزامي لكل الأدمن أم للأدوار العليا فقط؟ العليا فقط
7. **لغات الواجهة والترجمات** المطلوبة في المرحلة الأولى. العربية + الإنجليزية
