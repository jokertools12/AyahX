# اختبارات AyahX باستخدام tester-army/e2e

التكامل داخل `tooling/e2e` مستقل عن حزم التطبيق المنشور: `e2e 0.18.0`
و`@e2e-dev/web 0.13.0` بإصدارات مثبتة وملف lock مستقل. لا يحتاج تعديل Railway.

## التشغيل

من جذر المشروع، استخدم Node 24.8+ أو Node 22.22.3+:

```powershell
npm ci
npm --prefix tooling/e2e ci
npm run test:e2e
```

الأمر يبدأ Vite على `127.0.0.1:4188` ويوقفه عند الانتهاء. يجب أن يكون المنفذ
متاحًا. Chromium ينزل تلقائيًا إذا لم يكن موجودًا. لفتح المتصفح أثناء الاختبار:

```powershell
npm run test:e2e:headed
```

## اكتب طلبك بالعربي في Codex

مش محتاج تكتب ملف اختبار أوامر المتصفح بنفسك. اكتب هنا هدف الاختبار، وسأتبع
`.agents/skills/e2e/SKILL.md` لفهمه، وكتابة اختبار مناسب، وتشغيله، ومراجعة
النتيجة. إذا أثبت الاختبار خللًا في السلوك المطلوب، أعدّل الكود المسؤول
وأعيد الاختبار، ثم أشرح لك التغيير والنتيجة بالعربية. أمثلة:

- `أضف اختبار إن زر إنشاء الفيديو من الرئيسية يفتح صفحة الإنشاء على الموبايل.`
- `اختبر رحلة التسجيل حتى ظهور التحقق، وأصلح أي مشكلة تجدها.`
- `الاختبار ده فشل؛ راجع التقرير، حدد السبب، أصلحه، واختبره تاني.`

التغييرات تبقى محلية لتراجعها؛ لا تُدفع إلى GitHub أو Railway تلقائيًا.
اختبارات الواجهة الدقيقة لا تستهلك اشتراك النموذج. الخطوات التي تتطلب تفاعلًا
مرنًا باللغة الطبيعية تستخدم GPT‑6‑Luna من اشتراكك وقد تستهلك حدّه وترسل سياق الشاشة
الاختبار للنموذج. اختباراتنا لا تسجل حسابًا حقيقيًا أو تدفع أو تحذف أو تنتج
فيديو على الخوادم الحية.

لعرض الاختبارات أو تشغيل هدف واحد:

```powershell
npm --prefix tooling/e2e run list
npm run test:e2e -- --target mobile
```

التوثيق الرسمي يوصي بـWSL على Windows. تم تجربة التشغيل المباشر على جهاز
Windows الحالي أيضًا؛ مسار CI المعدّ يعمل على Ubuntu. تثبيت WSL ليس جزءًا
من هذا التكامل.

## التغطية وحدودها

خمسة سيناريوهات تتكرر على desktop بعرض 1440 وmobile بعرض 390:

- ظهور شعار AyahX الأصلي وتحميله، RTL، وعدم تجاوز العرض.
- تبديل الثيم وبقاؤه بعد الانتقال إلى صفحة أخرى.
- فتح حقول التسجيل واستعادة الحساب والانتقال إلى الدعم دون إرسال نماذج.
- الوصول إلى إنشاء فيديو من قائمة التنقل العادية والمحمولة.
- صفحة الرابط غير الموجود والعودة إلى الرئيسية.

التشغيل المحلي يعيد 503 لطلبات API المقروءة عمدًا لاختبار الواجهة عند غياب
الخلفية. لا يثبت سلامة قاعدة البيانات أو التسجيل أو الدفع أو إنتاج الفيديو.
طلبات تعديل API محظورة. لا يوافق الاختبار على الشروط ولا ينشئ حسابًا.

يمكن فحص واجهة موقع قائم مع طلبات GET الحقيقية:

```powershell
$env:AYAHX_E2E_URL='https://ayahx.com'
npm run test:e2e
Remove-Item Env:AYAHX_E2E_URL
```

## اختبارات اللغة الطبيعية الاختيارية

يوجد سيناريو agent لفتح تسجيل الدخول من التنقل. يستخدم اشتراك ChatGPT مباشرةً،
والموديل مضبوط على `gpt-6-luna` وفق وصفة اشتراك OpenAI الرسمية في e2e:

```powershell
npm run e2e:login
npm run e2e:models
npm run test:e2e:agent
```

للبحث الاستكشافي من وصف عربي واحد، استخدم الأمر التالي. هو يشغّل الوكيل على
نسخة AyahX المحلية ويكتب تقريرًا؛ اطلب مني بعده إصلاح الخلل وإعادة الاختبار:

```powershell
npm run e2e:explore -- "راجع رحلة إنشاء الفيديو على الموبايل وابحث عن مشاكل بدون إرسال أي نموذج"
```

`e2e login openai` يحفظ دخول الاشتراك بإدارة الأداة. تحقّق من أن `models openai`
يعرض المعرّف في حسابك قبل التشغيل. تم التحقق من تسجيل الدخول فعليًا وظهور
GPT‑6‑Luna بالمعرّف `gpt-6-luna`. اختبار الوكيل نجح على desktop وmobile بأربع
استدعاءات من اشتراكك. الطلبات ترسل صورة وسياق واجهة الاختبار وتستهلك حد
اشتراك ChatGPT. التجربة محدودة بثماني خطوات وعنوان محلي،
ولا تدخل بيانات الحساب ولا ترسل نموذجًا. لا تحتاج مفتاح API ولا تستخدم جلسة
Codex أو مفاتيح Railway. لا تختبر بيانات خاصة في جلسة agent.

## النتائج وCI

النتائج في `tooling/e2e/.e2e/`: `report.json` و`junit.xml` و`summary.md`،
مع traces ولقطة الفشل عند الحاجة. المجلد مستبعد من Git؛ قد يحتوي بيانات جلسة.
كل أوامر التشغيل المجهزة تعطل telemetry باستخدام `E2E_TELEMETRY_DISABLED=1`.

`.github/workflows/e2e.yml` يشغل المجموعة بدون AI على PR والتغييرات ذات الصلة
في main، ويرفع تقارير الاختبار لمدة سبعة أيام. التشغيل على GitHub يتطلب رفع
هذه الملفات؛ تجهيز workflow محليًا لا يثبت نجاحه على GitHub.

المصادر الرسمية:
[Quickstart](https://e2e.tester.army/docs/quickstart)،
[Web](https://e2e.tester.army/docs/web)،
[Config](https://e2e.tester.army/docs/reference/config)،
[Models](https://e2e.tester.army/docs/models)،
[CI](https://e2e.tester.army/docs/ci).
نسخة التوثيق المطابقة للإصدار موجودة في `tooling/e2e/node_modules/e2e/docs`.
