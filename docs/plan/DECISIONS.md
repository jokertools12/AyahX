## حالة تنفيذ D2 عند التوقف

في 2026-10-09 خرج أمر staging بالرمز 1، ثم أثبتت المصالحة للقراءة فقط وصول كامل بيانات D2 وسلامة D1 والجداول الحرجة. قراءة المتابعة أثبتت عدم بلوغ حد MySQL وعدم وجود جلسة root محلية غير جلسة التشخيص. الخطأ اللاحق يثبت بلوغ حد Railway SSH في وقته؛ لا يثبت وحده سبب exit1 الأصلي. لم تُعد الكتابة ولم يُطبّق الإنتاج. المصالحة ليست applied=true، وحارس staging لم يُغيَّر. نتائج offset الأصلية 8passed/48failed/13source_unavailable محفوظة. التوقف الآن لاعتماد جدول المصالحة ومعالجة تعارض status قبل أي SQL جديد؛ ثم التسلسل أعلاه، مع إذن نهائي منفصل للإنتاج. D2 غير مغلق.

## ترتيب السلطة والدليل

الكود الحالي يغلب وصفًا قديمًا في الخطة، وقرارات المستخدم تغلب الاثنين عند تحديد سياسة التنفيذ. جميع نتائج التشغيل الفعلية في `docs/data-audit.md` و`docs/railway-ops-log.md` وتقارير `docs/data/d2-*`. الأرقام في التقارير أدلة snapshots وليست ثوابت منتج. أي قبول مرحلة يعتمد على نتيجتها الفعلية، وليس build وحده.
