# مراجعة كود D4 قبل الدمج

المراجعة تغطي القيود الثلاثة، المخطط الإضافي وrollback، مصدر الملف المرخص، ربط الأدلة ببصمة المصدر والتوقيت، سياسة الظهور العام، حواجز العلم المغلق، SSRF، التخزين والمهام الدورية. لا routes أدمن أو واجهة جديدة في هذه المرحلة.

- الصحة: اكتُشف أن الملف المرخص الأقصر من إحداثيات الكلمات قد يُفعّل قبل أن يرفضه Resolver؛ أُصلح الرفض قبل تبديل المؤشر، واختُبر على MySQL وR2 وffprobe فعليًا. الأدلة: [القبول](d4-licensed-catalog-r2-short-acceptance.json).
- سلامة البيانات: CHECK الخاص بـsurah_slice القديم كان يمنع المسار المرخص، رغم قبول قيدي offset/publication. جرى استبداله فقط بعد مطابقة تعبيره الفعلي ببروفة محلية، مع الحفاظ على الفرع الأصلي وعدم منح global offset. [القيود الثلاثة](d4-three-gate-final-acceptance.json).
- وضوح التشخيص: ترتيب JSON_ARRAYAGG ليس عقدًا ثابتًا. المقارنة الجديدة تحفظ جميع خصائص الأعمدة والمفاتيح وعدد التكرارات؛ 39 اختبارًا تحمي تبدّل القيم والحذف والإضافة، مع قراءة إنتاجية مستقلة بلا كتابة. التقرير الفاشل السابق محفوظ.
- البنية: الظهور العام له دالة واحدة، وتحويل إحداثيات الريندر محصور في toRenderTimeline. لا ربط للواجهة أو الريندر القديم، ولا fallback بين تلاوات.
- الأمن: رموز RW/RO منفصلة حسب الحاوية، روابط قصيرة العمر، مضيف الحساب دقيق، وفحص DNS وكل قفزة. لا أسرار في Git أو أدلة الاختبارات العامة؛ الملفات المحلية الخاصة لم تُحذف أو تُنقل لتجاوز الرفض السابق.
- الأداء: القراءة الدورية محدودة ومقفلة، وتكتب تقارير وتدقيقًا فقط. قد تصبح إعادة التحقق من بصمة توقيت كل فصل مرخص مكلفة عند تراكم ملفات كثيرة؛ هذا تحسين لاحق يحتاج قياسًا، ولا يضعف بوابات الصحة الآن.

لا عائق كود مفتوح بعد إصلاح الملف القصير والمقارنة. يبقى قبول الشحن مستقلاً: CI ثم نشر SUCCESS وhealth/ready ولوج10دقائق وsmoke قراءة، مع rollback عند التراجع. الاختبارات المحلية وحدها لا تعلن إغلاق D4.
