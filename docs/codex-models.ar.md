# تشغيل خطة AyahX بالنماذج الثلاثة

فُعّل التنفيذ الكامل بطلب المالك بتاريخ 15 أكتوبر 2026، بعد مرحلة التجهيز.
الإعداد خاص بهذا المشروع، وملف Codex الشخصي لم يتغير.

## توزيع العمل

| المسؤول | النموذج | مستوى التفكير | الشغل المناسب |
| --- | --- | --- | --- |
| المنسق الأساسي | GPT-6.1 Sol | medium | ترتيب الخطة، التنفيذ الأساسي، دمج النتائج والتحقق |
| ayahx_luna | GPT-6 Luna | medium | فحص محدد، fixtures، توثيق وتعديلات صغيرة واضحة |
| ayahx_sol | GPT-6.1 Sol | medium | شريحة مستقلة تحتاج تنفيذًا عبر أكثر من طبقة |
| ayahx_astra | GPT-6 Astra | low | مراجعة القرارات الحساسة أو مشكلة مثبتة لم يحلها Sol |

Sol يرسل المهمة المناسبة ويرجع نتائج الوكلاء لبعضهم عند الحاجة. المحادثة الرئيسية
تظل على النموذج المختار؛ توزيع العمل يتم بتشغيل وكلاء بنماذج مختلفة. لا يوجد هنا
تبديل عشوائي للنموذج الرئيسي أو مدير خارجي يعمل دائمًا بالخلفية. هذا مدعوم بواسطة
[وكلاء Codex المخصصين](https://learn.chatgpt.com/docs/agent-configuration/subagents).

اخترنا الإعدادات كبداية مناسبة لهذا المشروع، وليست نتيجة benchmark شامل. اختيار
Luna للعمل المحدد وSol للتنفيذ وAstra للحالات الأصعب يتفق مع
[إرشادات اختيار النموذج](https://developers.openai.com/api/docs/guides/model-selection).
ارفع التفكير فقط عندما توضح نتائج مهمة فعلية أن المستوى الحالي غير كافٍ.

## كيف نوفر الليمت

- سقف وكيلين فرعيين بالتزامن، والمنسق لا يشغلهم لو المهمة أسهل ينفذها بنفسه.
- Luna يبدأ بالعمل المحدد؛ يرجع الغموض أو أول إصلاح فاشل إلى Sol.
- Astra يدخل بسؤال أو diff واضح، عند قرار حساس أو بعد محاولتي إصلاح موثقتين.
  جولة مراجعة واحدة ثم متابعة واحدة فقط لو ظهرت تغييرات مهمة.
- لا نرسل المحادثة والخطة كاملة لكل وكيل؛ نرسل الملفات والمتطلبات اللازمة فقط.
- لا نقاش مفتوح بين الثلاثة، ولا وكلاء داخل وكلاء، ولا تعديل متزامن لنفس الملف.
- سجلات ثابتة تمنع إعادة الفحص من الصفر عند استئناف العمل. الاختبارات تتكرر عند
  تغير ما يؤثر عليها، لا لمجرد الاطمئنان.

السقف المتزامن إعداد فعلي. اختيار المهام وعدد جولات المراجعة وحدود الردود تعليمات
يتبعها المنسق؛ ليست سقف توكنز تقنيًا. كل الوكلاء يستهلكون الليمت المشترك للحساب.
لا توجد نسبة توفير مضمونة، ولا إعادة ضبط لليمت أو شراء رصيد أو إعادة محاولات بلا حد.

## الاستخدام من تطبيق Codex

افتح المشروع `C:\Users\cpazi\Desktop\ayahX` في جلسة جديدة. اختر **GPT-6.1 Sol / Medium**
للمنسق إذا كان محدد النماذج يحتفظ باختيارك القديم. الإعداد المشروع لا يغير اختيار
جلسة قائمة؛ اختيارات الواجهة أو CLI الصريحة يمكن أن تتقدم على القيم الافتراضية،
طبقًا لـ[مرجع الإعدادات](https://learn.chatgpt.com/docs/config-file/config-reference).

عندما تريد بدء التنفيذ أرسل:

```text
استكمل تنفيذ الخطة وفق التفويض الحالي. اقرأ .codex/ORCHESTRATION.md ثم
.codex/prompts/start-enterprise.ar.md والتزم بهما.
فوّض المهام المناسبة إلى Luna وSol وAstra، مع سقف وكيلين فرعيين.
استكمل من docs/implementation/ayahx-plan/NEXT_SESSION.md،
وتحقق من كل شريحة وحدّث السجل، ثم staging وproduction بعد البوابات المعتمدة.
```

التشغيل يعتمد على أن جلسة Codex مستمرة. بعد إغلاقها أو نفاد الليمت لا يوجد وعد
بإكمال الخطة تلقائيًا في الخلفية؛ السجل يحفظ موضع الاستئناف للجلسة التالية.

## الاستخدام من PowerShell

من مجلد المشروع، المعاينة الافتراضية تعرض الإعداد فقط:

```powershell
.\tooling\codex.ps1
```

فحص الإعداد ووجود النماذج في الكتالوج، دون بدء تنفيذ أو inference:

```powershell
.\tooling\codex.ps1 -Mode Check
```

**الأمر التالي يبدأ تنفيذ الخطة فعلًا عند تشغيله لاحقًا**، داخل Codex التفاعلي:

```powershell
.\tooling\codex.ps1 -Mode Start
```

الأمر يثبت Sol/medium ويرسل مسار المشروع الفعلي والبرومبت. لا يحتاج API key جديدًا؛
يستخدم تسجيل دخول Codex الحالي. لا يشغّل التطبيق أو Railway أو مزود AI الخاص
بالتطبيق أثناء Preview/Check. إذا كان Codex غير مسجل أو نموذج غير متاح، يظهر الخطأ
بدل تبديل المزود بصمت. وجود النموذج في الكتالوج ليس ضمانًا لتوفر حصته لحظة التشغيل.
